## Release tooling follow-up

The candidate audit accepts a documentation-only evidence commit through `VALIDATED_SHA`, but the release operator and release workflow currently require the workflow HEAD to equal the artifact SHA. That contract makes it impossible to persist post-build evidence before release without creating a new candidate. For this release, the exact operator-equivalent `release.yml` dispatch was issued manually against the already validated SHA after all formal and artifact gates passed. A later tooling-only change should make the operator accept a documentation-only descendant while continuing to release and tag the immutable validated SHA.
