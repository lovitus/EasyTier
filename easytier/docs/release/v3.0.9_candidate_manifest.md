# v3.0.9 Candidate Manifest

## Intended build snapshot

Target validation branch: `codex/profiling-beta`.

Base: the latest post-v3.0.8 repository head,
`f20c10488508b7b09349a1965408a9d9f0d8d976`, including the release portability
and command-environment documentation committed after tag `v3.0.8`.

The candidate contains:

- a WireGuard listener fix that dispatches an in-flight datagram through the
  `Arc<WgPeer>` captured by its first peer-table lookup;
- a test-only synchronization hook and deterministic regression test that
  removes the captured peer before dispatch resumes;
- coverage for both ordinary `wg://` listeners and WireGuard VPN Portal through
  their shared `WgTunnelListener`;
- version 3.0.9 metadata, release notes, changelog, this manifest, and the
  validation matrix;
- the pre-existing non-build TODO
  `cross_platform_underlay_route_purification.md`.

The candidate intentionally does not change peer expiry, stopped-peer cleanup,
handshake replacement, stealth behavior, listener configuration, dependencies,
platform `cfg`, protobuf, generated files, or non-WireGuard transports.

## Root-cause and transport boundary

The unsafe second lookup was introduced by
`577cef131b92a4aada4374ad53ad52a344c03d71` (`fix wireguard deadlock`,
2024-04-28), when `WgPeer` table entries became `Arc<WgPeer>` and dispatch
changed from a held mutable map guard to a cloned peer obtained by
`get(...).unwrap()`. The same commit retained the independent one-second
expired/stopped-peer cleanup loop, leaving a removal window before that lookup.
Later packet-classification changes added a first lookup but retained the
second fallible lookup.

Ordinary `wg://` listeners and WireGuard VPN Portal both instantiate
`WgTunnelListener`, so they share the defect and the fix. The UDP listener
handles a missing table entry through explicit branches, while QUIC's analogous
stealth session classification and cleanup occur under one mutex. TCP, WS/WSS,
QUIC/QUIC-Brutal, UDP, and FakeTCP do not contain this WireGuard
cleanup/dispatch double lookup.

## Mandatory `.160` pre-push gate

Sync the complete snapshot to `192.168.2.160`, then run:

- `cargo test --locked --no-run --package easytier --lib` with default release
  features and with the focused `wireguard,quic` feature set;
- `cargo test --locked --no-run --package easytier-web`;
- the exact
  `wg_listener_survives_peer_cleanup_between_lookup_and_dispatch` test;
- the complete `tunnel::wireguard::tests` focused suite serially;
- focused frontend-lib Vitest plus frontend-lib, frontend, VPN plugin, and GUI
  production builds in dependency order;
- version, lockfile, platform-`cfg`, workflow-pin, generated-file, and complete
  diff audits.

The deterministic test must prove this exact interleaving:

1. listener captures an existing peer;
2. the test removes that peer from the shared map;
3. listener dispatch resumes through the captured `Arc`;
4. the listener task remains alive and the removed peer is not reinserted.

## Candidate workflows

After the remote gate:

1. push the single frozen candidate to `codex/profiling-beta`;
2. reuse the automatically started profiling and Android candidate workflows;
3. do not dispatch a duplicate run for the same SHA.

Before formal release, inspect the exact profiling artifact's SHA, build info,
checksums, symbols, target, static/static-PIE properties, version, and
executable mode.

## Linux exact-artifact evidence

- run the deterministic test on the Linux builder to simulate the formerly
  fatal cleanup/dispatch overlap;
- deploy the exact profiling artifact to isolated Linux validation hosts;
- establish and tear down ordinary WG tunnels repeatedly on explicit ports;
- exercise stopped-peer cleanup, idle expiry/reconnect, bidirectional payload,
  process liveness, logs, FD/thread return, and absence of WireGuard listener
  panic;
- smoke the WireGuard VPN Portal shared-listener path where configuration
  permits;
- keep other protocol listeners on explicit non-default ports and verify
  ordinary TCP/UDP connectivity is unaffected.

Android is unavailable under the current repository instruction. Treat the
automatic Android workflow as compile/package regression evidence and do not
reconnect to or mutate a device.

## Formal release gates

- dispatch formal Core first and require exact-SHA MIPS and MIPSel success;
- audit both 32-bit artifacts for architecture and endianness;
- only then dispatch GUI, Mobile, OHOS, and Test against the unchanged frozen
  release ref;

- publish tag `v3.0.9` only if every required gate remains green.
