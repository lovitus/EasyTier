## Non-blocking upstream-hardening boundary

- A prior review inspected the wrong worktree. Its findings are not evidence against this release candidate; the release worktree is `codex/v3.0.13-release` at the immutable SHA above.
- Runtime control already uses the 190-second `run_network_controller()` timeout, and unsupported browser-side runtime controls remain hidden by capability `v-if`; those items require no v3.0.13 change.
- The legacy packet descriptor ordering was introduced upstream by moving validation after the legacy branch. Upstream `1e40350c896e2635fbb7cc2804819cd25001b028` still has that ordering, but its server now uses defensive `Option` handling and no longer exposes the same descriptor `unwrap()` panic chain. EasyTier retains this as post-release upstream hardening, not a v3.0.13 blocker.
- Empty Apple packet-info framing remains a defensive hardening item for the explicit macOS/iOS paths. FreeBSD compiles related framing code but is not currently configured with `has_packet_info=true`, so it is not listed as a proven affected platform.
- Negative RPC timeout normalization and peer-ID collision recovery require broader, independent designs. They are deliberately excluded from this release rather than patched speculatively.
- Follow-up order: move descriptor validation before all branches and retain server-side `Option` defense; replace direct packet-info indexing with `first()` plus empty/IPv4/IPv6 tests; optionally synchronize upstream's non-panicking sender handling; then address timeout and peer-ID recovery separately.
