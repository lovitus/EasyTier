# v3.0.15-2 Candidate Manifest

Status: READY_FOR_CANDIDATE_COMMIT

## Purpose

Repair the Android underlay connector regression introduced by `d7be2a12` and
first released in v3.0.6. Android intentionally does not perform native
interface inspection, but the cached-snapshot integration required a snapshot
before reaching the existing mobile-platform bypass when `bind_device = true`.

## Immutable scope

- Base: `ab17763b6dc1778d1fbd80c93e9f049bc07ef9d0`, the accepted v3.0.15-1
  release-process head integrated into `codex/current`.
- Version: `3.0.15-2` on every Cargo, Tauri, GUI and Android delivery path.
- Leaf SHA: `682d1dc43585a703c993e8875fe4e937b1038733`.
- HEV SHA: `97e74f1068bd924e740032382cdc94ca83741ae6`.
- Make the existing native-interface-inspection capability crate-visible.
- Let the resolved-bind helper receive an optional underlay snapshot and keep
  the platform decision and missing-snapshot error in that helper.
- Android, iOS, OHOS and macOS Network Extension continue without native
  interface inspection when no snapshot exists, matching their pre-v3.0.6
  ownership model.
- Native desktop/server platforms continue to fail closed when a required
  snapshot is absent.
- Add a deterministic contract test for both platform branches.
- Excluded: VPN lifecycle, Android network events, route selection, DNS,
  transport selection, packet processing, Leaf, Mihomo, GOST and configuration
  schema changes.

2. `scripts/release-operator.sh builder-preflight` on `.160`.
3. Direct execution of the exact EasyTier test binary for:
   - `mobile_platforms_skip_snapshot_while_native_platforms_fail_closed`;
   - `native_interface_inspection_matches_platform_ownership`.
4. Complete diff, lockfile, dependency pin, platform `cfg`, generated-file,
   credential and 64-bit atomic portability audit.

## Candidate workflow and validation plan

1. Dispatch Linux Profiling Beta and Android Policy Candidate together for the
   immutable SHA using `scripts/release-operator.sh dispatch-candidates`.
2. Verify Linux artifact checksums, build information, target and exact SHA; run
   bounded Linux compatibility and lifecycle smoke because the native desktop
   fail-closed path changed structurally but not semantically.
3. Upgrade the physical Android device without clearing application data.
4. Start the existing `bind_device = true` network through semantic automation
   and require:
   - VPN/TUN running;
   - initial peer connection succeeds;
   - no `bind-device connector has no underlay interface snapshot` event;
   - no one-second retry loop;
   - captured-UID probe succeeds when policy traffic is in scope;
   - stop/start cleanup leaves no VPN, task or process residue.
5. Only after candidate and real-device PASS, run Core, GUI, Mobile, OHOS and
   Test together for the same SHA.
6. Audit formal artifacts and both exact-SHA MIPS/MIPSel jobs before Release.
7. Publish `v3.0.15-2` as a prerelease and verify tag, target, checksums, assets
   and installed/archive smoke.

## 64-bit atomic portability classification

- MIPS/MIPSel-reachable production `AtomicU64` uses are provided by
  `atomic_shim` in `secure_datagram`, `peer_task`, `proxy_failover`,
  `p2p_endpoint_retry`, `peer_ospf_route`, `stealth`, `network` and
  `token_bucket`.
- The standard-library `AtomicU64` occurrences in `peer_conn` and
  `tunnel/common.rs` are test-only.
- The standard-library `AtomicU64` in `virtual_nic.rs` is gated by
  `leaf-policy-proxy` and is excluded from both formal MIPS targets.
- The only `fetch_max` hit is `AtomicVersion(AtomicU32)` in
  `peer_ospf_route.rs`; no `atomic_shim::AtomicU64::fetch_max` call exists.
