## Independent functionality and evidence

1. Default throttle behavior:
   - exact endpoint failures advance through 1/2/4/8/10-minute stages;
   - success and new endpoint keys retain first-attempt behavior.
2. Compatibility bypass:
   - startup and dynamic enable always allow attempts and keep the table empty;
   - re-enable starts from stage one without resurrecting stale state.
3. Existing P2P semantics:
   - Direct, priority, upgrade/fallback/probe, UDP/TCP hole-punch tests retain
     their existing scheduling and internal retry counts;
   - manual connectors and established tunnels do not enter the table.
4. Configuration surfaces:
   - TOML, CLI true/false, management round-trip, managed runtime update,
     frontend default, GUI checkbox, and generated protobuf full-field tests.
5. Resource boundary:
   - 65,536-entry hard cap, deterministic per-shard eviction, no packet hot-path
     lookup, and previously measured full-table throughput/RSS thresholds.

## Exact-artifact validation plan

Linux evidence:

- cold-start Direct establishment and protocol upgrade;
- relay path, forced Direct loss, and recovery;
- peer listener/IP change and immediate new-key attempt;
- UDP cone/symmetric and TCP simultaneous-open behavior;
- `lazy_p2p`, `need_p2p`, `disable_p2p`, priority, and opt-out combinations;
- bounded endpoint-stage counters, connection churn, CPU, RTT, and packet loss;
- IPv4/IPv6 and mixed-version interoperability on the assigned internal and
  public dual-stack hosts.

macOS GUI evidence:

- preserve and restore the existing user configuration;
- confirm the checkbox persists through GUI restart and reaches the running
  core;
- with `lazy_p2p=false` and `need_p2p=true`, compare default throttling against
  the opt-out on the same network;
- verify ordinary tunnel establishment, stable traffic, and GUI/Mihomo resource
  behavior.

Android is currently unavailable. Record the platform-unavailable exception;
do not reconnect to or mutate a device until the maintainer makes it available.
