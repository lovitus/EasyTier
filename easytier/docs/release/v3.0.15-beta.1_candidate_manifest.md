# v3.0.15-beta.1 Candidate Manifest

Status: READY_TO_COMMIT

## Purpose

This is a validation release for the reproducible release operator and packaged
artifacts. It is not promoted as a stable user upgrade.

## Immutable scope

- Base: `bc1ad81e`, the post-v3.0.14 canonical `codex/current` branch.
- Correct canonical release-branch resolution in the Codex worktree guard.
- Add guarded `.160` source synchronization with delayed deletion and persistent
  Cargo, Corepack, and Node dependency caches.
- Add explicit incremental and bounded-repair frontend dependency preparation.
- Add one ordered `.160` preflight command for Rust and all frontend stages.
- Add exact-SHA formal workflow status, Core-first dispatch, MIPS/MIPSel gating,
  duplicate-dispatch prevention, release audit, and Release dispatch.
- Keep the candidate worktree clean while allowing explicitly isolated,
  documentation-only WIP in other linked worktrees; non-documentation changes in
  any linked worktree remain a hard release-audit failure.
- Update package metadata to `3.0.15-beta.1` and add validation release notes.
- Excluded: mesh, routing, RPC, TUN, policy, Mihomo, Leaf, GOST, DNS, transport,
  GUI behavior, configuration schema, and dependency pin changes.

## Pre-build gate

```bash
scripts/release-operator.sh builder-preflight
```

The command must complete the locked Rust no-run/focused suite and the ordered
frontend-lib Vitest, frontend-lib build, frontend build, VPN plugin build, and
GUI build on `192.168.2.160`. Local `scripts/pre-commit-check.sh`, version/lockfile
consistency, complete diff, platform cfg, workflow pins, generated files, and
credential checks must also pass before the candidate is pushed.

## Formal validation plan

1. Dispatch Core for the immutable candidate SHA.
2. Require the Core workflow and both MIPS/MIPSel jobs to pass.
3. Dispatch GUI, Mobile, OHOS, and Test once for the same SHA.
4. Inspect formal artifacts for expected architectures, executable sidecars,
   versions, manifests, licenses, checksums, permissions, and macOS signatures.
5. Publish `v3.0.15-beta.1` with `make_latest=false` only after all five formal
   workflows and the release audit pass.
6. Verify tag/Release target, asset inventory, checksums, embedded versions, and
   one install/archive smoke from the published assets.

## Pre-build result (2026-08-09)

- Local shell syntax, diff whitespace, version/lockfile consistency, credential
  scan, and `scripts/pre-commit-check.sh`: PASS.
- `.160` locked Rust no-run: PASS; clean version build completed in 4m38s and the
  final cache-reuse run completed in under one second.
- Leaf/policy/SOCKS/netstack focused suite: PASS, including the three-node ACL
  test and lifecycle, DNS, Geo, mesh-entry, packet-backpressure, and macOS packet
  framing coverage selected by `leaf-remote-preflight.sh`.
- Quinn UDP integration binary: PASS, 8/8.
- Frontend-lib Vitest: PASS, 15 files and 122 tests.
- Frontend-lib build, frontend build, VPN plugin build, and GUI production build:
  PASS in the required dependency order. The final GUI Vite stage completed in
  9m28s with continuous CPU activity.
- The first process-validation pass exposed three tooling defects before any
  workflow dispatch: readonly environment forwarding, incomplete protection of
  `.corepack-*` caches, and reuse of a corrupt fixed Corepack home. The final
  candidate uses `env`, protects every `.corepack*` directory, and isolates
  Corepack by the `pnpm-lock.yaml` blob hash. No Cargo or Node dependency tree was
  deleted to recover the gate.
