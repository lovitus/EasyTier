The first formal-gate attempt at `c439fa0e7f8749d1f68ee9443cd0971096ea2fba`
is diagnostic evidence only, not a release candidate: Mobile and OHOS passed,
but Core and GUI exposed two Darwin packaging defects. The successor snapshot
keeps the same runtime implementation and:

- records the exact runtime-ad-hoc-signed Mihomo hash while preserving its
  workflow-resolved upstream source and binary hashes;
- uses the same `--options runtime` signing mode for Core and Tauri sidecars;
- normalizes GUI sidecars twice under their final bundle names before metadata

This successor changes only release provenance and packaging validation. It
does not change Core, GUI, mesh, policy, GOST, or Mihomo runtime behavior.

The formal GUI run for `b09c587c5b3b882e73a5a162b89b45cb2e964a22`
proved that both Darwin sidecars were validly signed, but its post-bundle
Mihomo verification did not receive the workflow-resolved release manifest.
That SHA is therefore not releasable. The successor explicitly supplies the
already-downloaded immutable manifest to both GUI bundle-verification steps;
it does not alter or weaken binary verification.

The next formal Core run for
`36e6cbe6836ee6308fcda7326bb99f9da65a2703` exposed a Windows i686-only
compile boundary that earlier fail-fast runs had cancelled before execution:
the Job Object constructor lacked its generated `Win32_Security` feature and
the owned job was stored as a non-`Send` raw `HANDLE`. The successor enables
that API feature and stores the same handle in the standard-library
`OwnedHandle`, preserving `KILL_ON_JOB_CLOSE` semantics while making the
sidecar supervisors valid Tokio tasks. A Windows-only compile assertion keeps
`ManagedChild: Send` as an explicit invariant.

The formal GUI audit repair at
`6c3f013aed57899ecf905855dea9cbdeae6a2f25` passed its static workflow
boundary, but installed macOS validation exposed two nested startup deadlines.
Mihomo `main.go` handles `-t` by calling `executor.Parse()`, while
`component/geodata/init.go::downloadToPath` permits 90 seconds for each missing
Geo resource. A real first validation downloaded GeoSite and GeoIP in 58.7
seconds, exceeding EasyTier's former 20-second validator limit. Cached
validation then completed in 1.14 seconds but still exceeded the generic
five-second RPC deadline once the complete EasyTier and Mihomo startup path was
included. The successor:

- gives only the Mihomo validator a bounded 120-second limit;
- gives only `run_network_instance`, including disabled-to-enabled recovery, a
  190-second RPC deadline around the existing 180-second Core owner bound; and
- leaves short RPCs, Mihomo readiness, restart policy, routing, and data-plane
  behavior unchanged.

`6c3f013a` is diagnostic evidence only and must not be released.

The final GUI configuration repair keeps Leaf and Mihomo source ownership
independent. Existing `config_file/config_inline` remain the Leaf and legacy
source fields; new `mihomo_config_file/mihomo_config_inline` preserve native
Mihomo file or raw inline YAML. Legacy Mihomo envelopes migrate their shared
source once, while an explicitly empty Mihomo source fails closed instead of
borrowing Leaf YAML. Backend switching preserves both drafts and does not
change either parser or runtime data plane.
