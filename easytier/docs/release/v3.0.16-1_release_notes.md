# EasyTier v3.0.16-1

This prerelease lets a network reuse previously connected mesh peers as
auxiliary bootstrap addresses after a normal Stop or Exit.

## Bootstrap resilience

- Record live outbound peer URLs when a network stops normally.
- On the next start, append those URLs to the in-memory initial-peer list after
  the user's configured initial nodes.
- Keep independent snapshots for different network identities.
- Preserve the original remote hostname and path when available, while safely
  falling back to the resolved endpoint.
- Ignore malformed entries and never persist process-local `ring://` URLs.
- Replace a snapshot only when at least one live outbound URL is available, so
  an offline stop does not erase the last useful bootstrap data.

## Compatibility and boundaries

- User configuration files, GUI state and serialized initial-peer lists are not
  modified.
- No configuration migration or new user-facing option is required.
- Core, GUI/Tauri, Android JNI, FFI and OHOS entry paths use the same manager
  behavior and their existing platform-managed data directories.
- Snapshots are intentionally refreshed only by normal Stop or Exit. A crash or
  forced process kill does not attempt additional persistence.
- Cached URLs are supplemental hints. Configured initial nodes retain priority,
  and stale cached URLs fail like ordinary unreachable initial peers.
- Routing, hole punching, transport selection, policy engines, Leaf, Mihomo and
  GOST behavior are otherwise unchanged.
