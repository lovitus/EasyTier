## Frozen implementation scope

- Maintain exactly one primary bootstrap URL file and one fixed backup per stable network identity.
- Never replace a useful primary with an empty, identical, or strict-subset snapshot.
- Prefer the primary at startup and use the backup only when the primary has no valid URL.
- Reject `ring://`, malformed URLs, and tunnel schemes unsupported by the current build.
- Append recovered URLs only to the in-memory initial connector list; never modify user
  configuration.
- Preserve the v3.0.16-2 manual-connector retry and recovery semantics. The attempted
  manager-wide cooldown is excluded because formal tests proved that it delayed eventless recovery
  and destabilized existing P2P-only coverage.
- Persist through the existing manager shutdown path on normal Core signal, GUI Exit, Android
  stop, and Windows Service Stop.
- Keep the bootstrap state directory independent from Policy/Geo/Mihomo resource directories when
  Core runs without `--config-dir`.

## 64-bit atomic portability classification

- The exact lockfile pins `atomic-shim 0.2.0`. MIPS/MIPSel-reachable production
  `AtomicU64` uses in `p2p_endpoint_retry`, `proxy_failover`, `token_bucket`, `network`,
  `secure_datagram`, `peer_task`, `peer_ospf_route`, and `stealth` use that shim and only
  its supported fallback operations.
- Standard-library `AtomicU64` occurrences in `peer_conn.rs` and `tunnel/common.rs` are
  test-only.
- The standard-library `AtomicU64` in `virtual_nic.rs` is gated by
  `leaf-policy-proxy` on Unix and is excluded from both formal MIPS targets.
- The only `fetch_max` occurrence is `AtomicVersion(AtomicU32)` in
  `peer_ospf_route.rs`; there is no `atomic_shim::AtomicU64::fetch_max` call.
- Formal Core remains the non-waivable target proof: both exact-SHA MIPS and MIPSel jobs
  and their artifact architecture/endianness audits must pass before Release.
