# v3.0.16-2

## Changes

- Reduced the documented release path to four maintained operator commands.
- Starts the five formal workflows immediately after candidate success while exact-artifact and device validation run in parallel.
- Adds exact-SHA retry/resume handling for diagnosed infrastructure or flaky workflow failures.
- Removes unrelated historical recovery archives and parallel worktrees from routine release gating.

## Compatibility

- Runtime mesh, policy, GUI, mobile, and platform behavior is unchanged from v3.0.16-1.
- Existing low-level release commands remain available through `help-advanced` for recovery.

## Validation

- Exact candidate: `86c6a5752f110f4f25127c9e47fad10124850efb`.
- The complete `.160` Rust and frontend preflight passed before dispatch.
- Linux Profiling Beta and Android Policy Candidate passed before the five formal workflows were started together.
- Core, GUI, Mobile, OHOS, and Test all passed for the same SHA; both MIPS and MIPSel Core jobs passed.
- The optimized Linux artifact passed checksum, build metadata, sidecar, version, and no-residual-process checks on the internal compatibility hosts and the public dual-stack validation pair.
- The formal macOS ARM64 GUI artifact passed version, architecture, sidecar payload, and deep code-signature checks.
- The published Linux x86_64 ZIP was downloaded again and matched its GitHub SHA-256 digest and the audited formal Core binary.

## Release-process result

- One `validate` invocation dispatched the candidate pair, waited for both, and then dispatched all five formal workflows in parallel.
- A transient GitHub TLS failure was recovered by bounded exact-SHA retry without creating a duplicate workflow.
- The worktree guard now follows the single `origin/codex/current` integration pointer instead of guessing from stable tags or historical release branches.
- No runtime source changed in this prerelease; it validates the simplified release process itself.
