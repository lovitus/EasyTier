# EasyTier v3.0.6 Release Notes

EasyTier 3.0.6 adds an optional, decoupled Mihomo policy-routing backend for
desktop and Unix deployments, introduces a Core-owned GOST mesh SOCKS entry,
and fixes several macOS DNS, interface-change, and QUIC failure modes.

## Highlights

- Policy routing now supports `off`, `mihomo`, and the existing `leaf`
  compatibility backend. Mihomo receives a generated runtime copy of the
  user's configuration while the original YAML remains unchanged.
- Every supported Core package includes a managed GOST SOCKS5 service for the
  neutral mesh entry. Mihomo can use ordinary SOCKS5 `dialer-proxy` chains
  without EasyTier parsing or rewriting proxy nodes.
- The managed GOST service supports TCP and UDP, bounded restart supervision,
  loopback-only process listeners, explicit UDP buffer/source validation, and
  clean parent-owned shutdown.
- Desktop peer ingress binds only the instance's exact virtual IPv4 on
  `11080-11082`. It no longer sends desktop TCP through the old userspace
  smoltcp ingress. The exact optimized Linux candidate measured a median
  `200.471 Mbit/s` across five 32 MiB nested SOCKS transfers, compared with
  approximately `55 Mbit/s` on the superseded ingress.
- Exact nested UDP echoes of `64`, `1200`, and `8192` bytes passed before and
  after forced GOST restart. Normal Core shutdown removed GOST, Mihomo, SOCKS
  listeners, and TUN state.

## Reliability and compatibility

- macOS policy DNS now follows interface and resolver changes more reliably.
  Scoped routing and QUIC receive handling avoid stale-interface use,
  truncated-datagram spin, and starvation under sustained traffic.
- Mihomo and GOST child processes use bounded readiness, restart, and cleanup
  handling. Runtime state is exposed to Core and GUI instead of being inferred
  from a configured flag.
- The GUI validates policy configuration according to the selected backend,
  keeps node/group/rule editing compact, and reports backend and neutral mesh
  entry status consistently.
- Three-node and delayed-network tests were hardened without relaxing their
  functional assertions.
- Cached traffic metric handles are reused on the Core hot path. A separate
  experimental GRO scratch-buffer expansion was reverted after mixed-host
  profiling and is not part of this release.
- Formal Core and GUI packaging verifies Mihomo/GOST versions, manifests,
  licenses, source metadata, target architecture, executable permissions, and
  macOS signatures before release assembly.

## Platform boundaries

- Android continues to use the existing in-process Leaf/HEV policy path. The
  Mihomo backend is not enabled on Android or OHOS.
- The complete Mihomo -> local GOST -> mesh -> peer GOST TCP/UDP, restart, and
  cleanup matrix was validated on the exact Linux x86_64-musl candidate.
- macOS, Windows, and FreeBSD packages include their declared policy sidecars,
  but this release does not claim the same cross-host performance evidence for
  those platforms.
- Mihomo remains unavailable in release packages for targets marked
  `needs_review`, including current MIPS, MIPSel, ARMv7/ARM, and LoongArch
  mappings. Existing non-policy EasyTier operation remains available.

## 中文摘要

- 桌面和 Unix 平台新增可选 Mihomo 策略路由后端，同时保留 `off` 和现有
  Leaf 兼容模式。EasyTier 只生成运行时配置副本，不修改用户原始 Mihomo
  YAML，也不解析或改写代理节点。
- Core 内置托管 GOST SOCKS5 mesh 入口，支持 TCP、UDP、进程恢复和统一
  清理。Mihomo 可使用标准 `dialer-proxy` 通过 mesh peer 组成代理链。
- 桌面入口只监听实例的精确虚拟 IPv4 和 `11080-11082`，GOST 本身只监听
  loopback。Linux 精确优化制品的五轮 32 MiB 完整链中位数为
  `200.471 Mbit/s`，UDP `64/1200/8192` 字节在 GOST 崩溃恢复前后均通过。
- 修复 macOS DNS/接口变化和 QUIC 截断报文忙循环、饥饿问题，并完善
  Mihomo/GOST 状态、GUI 配置校验、三节点测试和正式制品校验。
- Android/OHOS 不启用 Mihomo；Android 继续使用现有 Leaf/HEV 路径。
