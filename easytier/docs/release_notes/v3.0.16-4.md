# v3.0.16-4

## Changes

- Treat peer URLs restored from the auxiliary bootstrap snapshot as runtime helpers rather than as
  permanent configured initial peers.
- Pause new reconnect attempts for those helpers after the node has rejoined the primary mesh, which
  avoids continued DNS/socket/log retry fan-out from stale cached addresses.
- Resume helper attempts automatically if all primary peer connections disappear, preserving
  eventless recovery without a new cooldown or network-change dependency.

## Compatibility

- Configured initial peers and connectors added through RPC retain their existing retry behavior and
  priority. User configuration and the bootstrap snapshot format are unchanged.
- An already in-flight helper attempt may finish once after another peer becomes live. No established
  connection is closed merely because it originated from a helper.
- If no primary peer is reachable, helpers continue using the established reconnect cycle so a
  long-offline node can still recover when an endpoint becomes reachable.
- Transport selection, authentication, relay, P2P, QUIC, KCP, FakeTCP, routing and packet forwarding
  behavior are unchanged.
