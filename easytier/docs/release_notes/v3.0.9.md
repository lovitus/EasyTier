# EasyTier v3.0.9 Release Notes

EasyTier 3.0.9 fixes a WireGuard listener concurrency race that could terminate
the whole process when peer cleanup overlapped an incoming datagram.

## WireGuard listener stability

The WireGuard listener previously looked up the same peer twice while a
background task was allowed to remove expired or stopped sessions. If cleanup
ran between those lookups, the second lookup panicked. EasyTier's production
panic handler exits the process, so a single unlucky overlap could stop the
entire node.

The listener now dispatches the in-flight datagram through the peer reference
captured by the first lookup. The `Arc<WgPeer>` keeps that peer valid for the
current operation even if cleanup removes it from the table; later packets
continue to observe the cleaned table and may establish a replacement session.

This one fix covers:

- ordinary EasyTier `wg://` listeners;
- the WireGuard VPN Portal, which uses the same listener implementation;
- Windows, Linux, and macOS builds.

Session expiry, stopped-session cleanup, WireGuard handshake replacement,
stealth framing, and protocol-selection behavior are unchanged.

## Verification

The regression suite deterministically pauses packet dispatch after the first
peer lookup, removes that exact peer from the listener table, resumes dispatch,
and requires the listener task to remain alive. Release validation also
repeats the race on Linux with the exact candidate artifact before publication.
