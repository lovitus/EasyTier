# v3.0.16-3

## Changes

- Preserve a small set of previously working outbound peer URLs after a normal Stop or Exit, so a
  node can rejoin through a known peer when its configured initial node is temporarily unavailable.
- Keep one automatic backup and avoid replacing a useful bootstrap snapshot with empty, unchanged,
  or incomplete data during rapid stop/start cycles.
- Batch failed initial-peer retries behind a bounded, jittered cooldown to prevent unreachable
  cached endpoints from causing continuous DNS, connection, network, or log activity.
- Reset the cooldown promptly when connectors or the underlying network change.
- Explicitly persist the snapshot during normal Core, GUI, Android, and Windows-service shutdown.

## Compatibility

- User configuration and configured initial peers are never rewritten. Cached peer URLs are
  auxiliary runtime inputs stored under EasyTier's application state directory.
- Existing connector protocols, authentication, relay, P2P, QUIC, KCP, FakeTCP, routing and packet
  forwarding behavior are unchanged.
- The cache cannot recover expired NAT-only endpoints when no saved peer remains reachable; a
  rendezvous or otherwise reachable peer is still required for that topology.
- This prerelease is validated manually on Linux and Android. Other supported targets remain
  covered by the formal build/test workflows.
